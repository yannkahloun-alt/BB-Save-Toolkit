### 1. Progression des stats

Ce sont les tests les plus fondamentaux.

* `gain_range()` pour chaque famille de stat :

  * Initiative 0★ → 3–5
  * MAtk/MDef 0★ → 1–3
  * autres stats 0★ → 2–4
* Effet des stars :

  * 1★ augmente le minimum de +1
  * 2★ augmente le minimum de +2
  * 3★ augmente minimum de +2 et maximum de +1
* Tester toutes les stats × 0/1/2/3 stars.
* `average_gain()` doit être exactement le milieu de la range.
* `development_rounds_to_11()` :

  * niveau 1, aucun point pending
  * niveau 2 avec `LevelPoints=1`
  * niveau 10
  * niveau 11
  * niveau >11
  * éviter tout résultat négatif.

### 2. Courbe de Fit

`curve_value()` doit être verrouillé très précisément.

* valeur sous le premier point ;
* exactement sur chaque point ;
* interpolation entre deux points ;
* valeur au-dessus du dernier point ;
* segment avec `x0 == x1` ;
* courbe vide.
* Vérifier la continuité aux bornes.

Puis `weighted_role_score()` :

* une seule stat ;
* plusieurs stats de poids identiques ;
* poids différents ;
* stat `fit=false` ignorée ;
* rôle sans aucune stat Fit → 0 ;
* saturation au target ;
* valeur sous baseline ;
* score >100 si la configuration le permet ;
* composants retournés cohérents avec le score total.

### 3. Effets de perks sur les stats

Très important, car ces effets alimentent toute la projection.

* aucun perk → valeur effective = valeur brute ;
* `+=`, `-=`, `*=`, `/=`;
* plusieurs effets sur une même stat dans le bon ordre ;
* division par zéro ignorée proprement ;
* Colossus :

  * multiplication HP ;
  * arrondi par `floor`, pas round ;
* Fortified Mind :

  * multiplication Resolve ;
  * arrondi Battle Brothers positif (`floor(x+0.5)`), pas bankers-round Python ;
* effet sur stat non reconnue ignoré ;
* perk inconnu ignoré ;
* effet conditionnel ignoré ;
* effet non exact ignoré.
* `effective_values()` cohérent avec `effective_stat_value()`.
* `effective_stat_profile()` retourne les bons multiplicateurs.
* cache perks : reset puis résultat identique.

### 4. Structural perks

* `structural_projection_perks()` ne retourne que les perks :

  * présents dans `perk_model.json`,
  * exacts,
  * non conditionnels,
  * affectant une vraie stat.
* Vérifier explicitement que **Fortified Mind n’est pas structural**.
* Vérifier que Colossus l’est si c’est bien la config actuelle.
* `structural_projection_perk_stats()` retourne seulement les stats réellement modifiées.
* perk inconnu → aucune stat.

### 5. Sampling déterministe

C’est une zone importante parce qu’on veut éviter toute confusion avec Monte-Carlo.

* `_radical_inverse()` sur quelques valeurs connues ;
* `_sample_dimension()` :

  * même entrée → même sortie ;
  * valeurs dans [0,1) ;
* `_sample_coordinates()` :

  * bon nombre de samples ;
  * bon nombre de dimensions ;
  * déterminisme entre deux runs ;
* aucune utilisation d’un RNG aléatoire dans la projection.
* 512 samples identiques d’un run à l’autre.
* 2048 samples identiques d’un run à l’autre.

### 6. Normalisation des ranges de rolls

* ranges normales construites à partir des stars ;

* nombre de rounds inférieur à 10 ;

### 7. Moteur de trajectoire

C’est la partie la plus critique.

Tests unitaires de `project_fit_trajectory()` :

* zéro round → Fit actuel ;
* une seule stat Fit ;
* deux stats Fit ;
* trois stats Fit ;
* quatre stats Fit ;
* rôle où les 4 stats ont exactement le même intérêt ;
* choix de 3 parmi 4 correctement arbitré ;
* stat sous baseline mais rentable au niveau 11 ;
* stat déjà saturée au target → elle doit perdre de la priorité ;
* roll élevé sur stat faible vs roll moyen sur stat importante ;
* changement du poids modifie correctement le choix ;
* changement baseline modifie correctement le choix ;
* changement target modifie correctement le choix.
* Le premier choix ne dépend pas des vrais `FutureRolls`.
* Une future range probabiliste différente peut modifier le lookahead attendu, mais jamais via l’oracle caché.
* `forced_first_combo` est respecté.
* `include_trace=False` ne doit pas modifier le résultat numérique.
* `samples=1` avec ranges dégénérées → min=max=expected=P5=P95.
* Expected doit être compris dans full min/max.
* P5 ≤ Expected ≤ P95 dans les cas standards.
* P5/P95 inclus dans full range.
* Full min ≤ full max.
* feasibility entre 0 et 100.
* si tous les outcomes ≥100 → feasibility 100.
* si aucun outcome ≥100 → feasibility 0.
